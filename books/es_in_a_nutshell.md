# 一本书讲透es

## es索引

### 索引别名

索引别名可以指向一个或多个索引。
- 在正在运行的集群上进行一个索引和另一个索引之间进行透明的切换
- 对多个索引进行分组组合
- 在索引的文档子集上创建试图。结合业务场景，缩小检索范围。

```
post /_aliases
{
  "actions":[ 
    {
      "add" {
        "index": "index_1",
        "alias": "index"
      }
    },
    {
      "add": {
        "index": "index_2",
        "alias": "index"
      }
    }
  ]
}
```

### 别名的常见问题

1. es的批量插入操作可以使用别名实现？
  - 不可以向别名直接插入数据。除非在生命别名是添加*is_write_index*配置。所以在写入是最好还是使用物理index。
2. es如何获取别名的信息
  - `GET _cat/aliases?v`


### 索引模版

es模版用于定义一个index的一些参数。包含alias、mapping、settings。

7.8之后的es支持两种定义模版的方式。
- 普通定义模版方式
- 组件模版新增/创建方式
  - 组件模版的核心在于将原有的普通模版定义为mapping、settings等以组件的方式分割，以便最小化更新模版。

常见问题
1. 如果相更新索引，能否通过更新模版来实现呢？

首先需要建立一个认知前提：一旦创建了映射，除了几个特定的类型之外，其他类型都不支持更新，除非进行reindex操作。

所以，一旦创建索引，对索引模版的更新也将不会影响该索引。更新模版仅仅适用于新创建的索引。更新为动态模版仅仅会影响索引中的新字段。

## es映射

### 映射的定义

#### 多字段类型功能

es允许用户对单个文档字段设置多个不同的数据类型过，以满足不同查询需求。

https://www.elastic.co/guide/en/elasticsearch/reference/current/multi-fields.html#multi-fields

实际的使用方式是。
- 一个字段可定义多个子字段，每个字段可以指定不同的字段类型。当查询或排序时，直接使用合适类型的子字段。

#### 映射类型

*动态映射*
- 动态映射会自动检测字段类型，然后添加新字段。
- 支持动态检测的数据类型。boolean、float、long、object、array、date、字符串类型。除此之外的类型会被适配为text类型。

*静态映射*
- dynamic=false。 忽略新字段，包含新字段的数据写入不会报错，但数据未被写入。
- dynamic=strict。数据写入时就报错，阻止数据写入。


#### 问题：映射创建之后还可以更新吗？

大多数情况下，已经定义的字段不可以更新，除非通过reindex操作来处理。

不过一下三种情况，可以直接更新。
- 向object中添加新字段
- 向已经存在的字段里面添加fields，以创建一个字段的多类型
- ignore_above是可以更新的。

### Nested类型及应用

对于嵌套文档，在使用的时候需要显声明为Nested。不然查询时，结果可能会我们预想的不同。

### Join类型

Join数据类型，主要用于模拟关系型数据库中的多表关联操作。

- 父表和子表的数据都在相同的index中
- 子文档的路由值时必须的，因为父文件和子文件必须在相同的分片上创建索引。
- 对于每个索引，仅允许定义一个与join类型关联的映射。
- 一个文档可以有多个子文档，但一个子文档只能有一个父文档。

> 什么是路由值?
  - es的数据会进行分片处理。固定的路由值对应固定的数据分片。

### Flattened类型及应用

将一个object字段仅仅使用一个keyword字段存储，数据不会丢失。适用于数据的字段数量无法确定的情况，而且这样可以避免字段暴增。

不过Flattened也有部分局限，仅支持基本的查询。使用的时候需要留意。

### 内部数据结构解读

- 倒排索引: 适用于对文档进行关键词搜索。
- doc_value: 大部分字段都会自动创建doc_value，除了text类型。doc_value的使用场景时排序、聚合和精准查找。
- fielddata: 
  - 仅仅适用于text类型。当text字段被用于聚合、排序或脚本操作的时候，会根据数据的倒排索引实时创建（代价很高）。
- _source: 
  - 包含文档被创建时的原始json。_source并没有被创建索引，因此不可搜索。可以禁用这个功能，以节省存储资源。不过会有一定的副作用，少部分功能会受影响（需要权衡）。
- store:
  - 数据存储数据到index，但不存储数据进入_source。这也就意味着，可以通过字段进行查询，但对应的字段却没有数据。（真是奇怪）
  - 大部分情况不用关注。除非手动关闭_source

### null_value详解

null值无法被索引和查询。空列表和全为null的列表，都被视为数据丢失。

通过null_value，可以将显式的null值，替换为被指定的值，使其可以被查询。

*需要注意的点*
- null_value仅仅会影响index中的值，不会_source中的值
- null_value保持和字段的类型相同

## es查询

### 精准匹配：
- term
- terms: 类似于`field in ["1", "2", "3"]`
- terms_set: 给定的列表字段，必须包含查询的枚举中N个。不过terms_set的使用方法奇怪。
  ```
  # 使用minimum_should_match_script & max 可以达到想要的目的。
  GET my_index_0003/_search
  {
    "query": {
      "terms_set": {
        "genre.item": {
          "terms": [
            "Crime"
          ],
          "minimum_should_match_script": {
            "source": "Math.max(0,1)"
          }
        }
      }
    }
  }
  ```
- range: 范围查找
- wildcard检索: 通配符检索
- regexp检索：正则匹配检索
- prefix检索: 前缀匹配检索
- fuzzy检索: 支持编辑距离的模糊检索。有效提高了搜索容错的能力。
  - 编辑距离: 从一个单词转换到另一个单词需要编辑单字符的次数。
- ids检索: 通过doc id进行查询数据。
> term/terms/terms_set对于列表字段同样适用。
  
### 全文匹配
- match
- match_phrase: 保留文本查询的顺序。
- multi_match: 支持通过从多个字段查询。并且可以设置字段的权重。
- query_string
  - 自此多字段的于或非的查询关系。

### 分页查询

#### from + size:
- 支持随机跳转分野
- 存在最大窗口限制。而且越向后翻，性能越低。

#### pit + search_after
- 只能向后翻。适用于超过10000页数据结果的场景
- pit是为了保证数据的一致性。保证在使用search_after翻页数据时，数据不会发生变更。

什么是pit（Point In Time）？

es内部一种轻量级的视图，创建时可以设置TTL（keep_alive）。keep_alive不用很长，每次查询都会自动续加keep_alive的时间。

#### scroll

遍历全部数据。官方不再推荐这种做法。


## es核心工作原理

### 文档版本问题

es的文档中有定义一个*_version*字段。当对文档进行更新、索引和删除，_version都会增加1.

**es内部的锁是一个种乐观锁**。

主要有2种使用方式
- 使用external对版本号进行外部控制。

  使用external版本管理时，es在处理索引请求时会对比传入文档的版本号和已经存储文档的版本号。如果传入的版本号大于已存储的，就表明这是一个新版本的文档，es则会执行索引操作并更新文档的版本号。然而，如果传入的版本号小于或等于已有版本号，则代表可能存在并发修改的问题，索引操作会被拒绝。


  ```
  PUT my_index_001/_doc/1?version=1&version_type=external
  {}
  ```

- 使用*if_seq_no* & *if_primary_term*作为唯一标识来避免版本冲突

  在执行索引写入操作时，es会检查传入的if_seq_no & if_primary_term是否于最后一次修改文档的seq_no&primary_term匹配。

  ```
  PUT my_index_001/_doc/123?if_seq_no=0&if_primary_term=1
  {}
  ```
